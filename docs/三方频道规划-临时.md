## 已确认的收敛方向

- Hash 请求只表示获取与 SHA-256 严格对应的文件字节，不再使用 `resource.kind`；
- 三方频道处理 Hash 广播和私密消息投递，不定义后续文件传输协议；
- 每个 WebRTC offerer 为自己的连接生成独立 `session_id`；
- 公开消息和私密消息使用两种不同的消息壳：公开壳直接承载业务体，私密壳只暴露解密所需字段并承载密文；
- libp2p 已认证公钥是 SSP 调用者和付款身份；CP 报文自带发送者公钥与签名，两者可以不同；
- 所有私密消息都进入稳定的 `bsv8.inbox.<public_key_hex>` 频道；
- 私密收件箱通过频道后缀确定接收者公钥，外层加密壳携带发送者公钥；解密后的消息不重复携带双方公钥；
- V1 使用双方长期 secp256k1 密钥执行 ECDH，不引入一次性 ECDH 密钥；每次加密必须重新生成 HKDF salt 和 AES-GCM nonce；
- 每条业务消息只做一次 ECDSA 签名；子协议只定义 `body`，不重复定义公共头、公钥或签名；
- Supplier 只原样交付 CP `content_json` 字节；两跳 SSP Wire 和 request_id 分别构造；
- WebRTC 和应用消息使用互不引用的强类型子协议结构；
- 应用消息由接收方主动返回 ACK，SSP Publish 成功不代表送达；
- Hash 频道和子协议名称包含 `bsv8` 命名空间及各自版本；
- locator 数组顺序表示尝试顺序，不再使用 `priority`；
- multiaddr 直接使用标准 `/dns4/...` 或 `/ip4/...` 字符串。
