# 应用消息子协议 V1

协议：

```text
bsv8.message.v1
```

本协议只定义 PrivateMessage body。CP 公共 message_id、时间、签名和 Inbox 发送者公钥不在
body 中重复。Deliver/ACK 的有效期最多 24 小时。

## 1. Deliver

```json
{"type":"deliver","content":{}}
```

`content` 是任意 JCS 兼容 JSON 值。Deliver 的关联编号是其 PrivateMessage
`message_id`。

## 2. ACK

```json
{
  "type":"ack",
  "acknowledged_message_id":"deliver-message-id"
}
```

ACK 是另一条独立的 CP PrivateMessage，有自己的 message_id、时间和签名；body 只引用
Deliver 的 message_id。

接受 ACK 前检查：

1. ACK 信封发送者是原 Deliver 的接收者；
2. ACK inbox 接收者是原 Deliver 的发送者；
3. acknowledged_message_id 等于 Deliver message_id；
4. 两条消息均已解密、验签且未过期。

ACK 表示 Deliver 已可靠保存或处理器承担后续可靠责任，不表示已读或业务成功。

## 3. 重试

未收到 ACK 时，可重新 Publish 同一条已签名 Deliver：

- message_id、时间、body 和签名保持不变；
- 每次重新加密可使用新的 salt/nonce；
- 接收方按 `(from_public_key, message_id)` 去重；
- 重复 Deliver 不重复执行应用业务，但可以重新发送新的 ACK。

SSP request_id 和收费重试独立于上述 CP 重试。

## 4. 结构隔离

- Deliver 只允许 `type/content`；
- ACK 只允许 `type/acknowledged_message_id`；
- body 不允许公钥、签名或公共消息头字段。
