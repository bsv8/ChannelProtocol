# 应用消息子协议 V1

子协议名称：

```text
bsv8.message.v1
```

本协议只定义私密消息的 `body`。公共 `protocol`、`message_id`、时间和唯一 `signature`
由 [私密收件箱](./02-私密收件箱.md) 统一定义。

对应类型：

```ts
PrivateMessage<"bsv8.message.v1", MessageV1Body>
```

Deliver 和 ACK 私密消息的 `expires_at_ms - issued_at_ms` 都不能超过 24 小时。

## 1. Deliver Body

```jsonc
{
  "type": "deliver", // 投递应用消息
  "content": {}       // 应用自行定义的任意 JCS 兼容 JSON 值
}
```

Deliver 的关联编号就是外层私密消息的 `message_id`。Body 中不重复编号、公钥、时间或签名。

## 2. ACK Body

```jsonc
{
  "type": "ack",                          // 接收确认；不要求 ACK-of-ACK
  "acknowledged_message_id": "deliver-id" // 原 Deliver 私密消息的 message_id
}
```

ACK 是另一条独立私密消息，因此有自己的公共 `message_id` 和唯一签名，但 ACK body 不再
携带签名字段。

发送方接受 ACK 前必须确认：

- ACK 加密信封 `from_public_key` 等于原 Deliver 的 inbox channel 接收者公钥；
- ACK 的 inbox channel 接收者等于原 Deliver 加密信封的 `from_public_key`；
- `acknowledged_message_id` 等于原 Deliver 私密消息的 `message_id`；
- ACK 的时间、解密结果和唯一签名有效。

## 3. ACK 语义

ACK 表示：

> 接收方已经成功解密和验签 Deliver，并已持久化保存消息，或者由业务处理器明确承担了
> 后续可靠处理责任。

ACK 不表示用户已读、业务执行成功或返回了业务结果。需要这些语义时，由应用在
`content` 中定义新业务消息，不能重新解释 ACK。

## 4. 发送方状态

```text
PENDING
├── 收到有效 ACK ───────────────→ ACKNOWLEDGED
└── 等待期限结束仍无有效 ACK ──→ EXPIRED_UNCONFIRMED
```

`EXPIRED_UNCONFIRMED` 只表示发送方没有获得送达证明。消息可能没有到达，也可能已经到达
但 ACK 丢失；业务可以把该状态视为未送达。

## 5. 去重和重试

发送方未收到 ACK 时，可以重新 Publish 同一条已签名 Deliver 私密消息：

- 保持相同 `message_id`、时间、body 和唯一签名；
- 每次重新加密使用新的 `kdf_salt` 和 `nonce`；
- 不能修改 body 后继续使用原 `message_id`。

接收方：

```text
首次收到 Deliver
→ 验证并可靠接收 content
→ 记录 (from_public_key, message_id)
→ 返回 ACK

重复收到 Deliver
→ 不重复执行应用业务
→ 重新返回一条新的 ACK 私密消息
```

相同 `(from_public_key, message_id)` 携带不同的已签名消息内容时，必须按编号冲突拒绝。

## 6. 结构隔离

| `body.type` | 必需字段 | 禁止字段 |
|---|---|---|
| `deliver` | `content` | `acknowledged_message_id` |
| `ack` | `acknowledged_message_id` | `content` |

MessageV1Body 不能定义 `sdp`、`candidate`、`session_id`、身份公钥或 `signature`。应用自己的
`content` 即使包含同名业务数据，也不能改变 `protocol` 分派结果。

## 7. 交互流程

```text
发送者 A                    SSP 私密收件箱                    接收者 B
   │                                                            │
   │── 已签名并加密的 Deliver(M) ──────────────────────────────>│
   │                                      解密、验签、可靠接收 M │
   │<─ 已签名并加密的 ACK(acknowledged_message_id = M.id) ─────│
   │                                                            │
   │── 状态变为 ACKNOWLEDGED                                    │
```

双方加解密都使用自己的长期私钥和对方长期公钥。Deliver 与 ACK 分别是独立业务消息，每条
各有一个签名，不存在同一条消息重复签名。
