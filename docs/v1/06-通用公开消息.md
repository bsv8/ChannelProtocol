# 通用公开消息 V1

通用公开消息是任意精确 SSP public channel 上的统一 CP 签名原语。它提供公开 JSON
壳的严格解析、JCS 规范化和签名验证，不负责频道业务分派。

## 1. 线上形状

```json
{
  "from_public_key": "02...",
  "message_id": "base64url-32-byte",
  "issued_at_ms": 0,
  "expires_at_ms": 0,
  "body": {},
  "signature": "base64url-der"
}
```

`channel` 由调用方在消息 JSON 外提供，不写入线上壳；它必须是非空、非 `*`、不含
控制字符、不超过 256 个 UTF-8 字节的精确频道。`body` 可以是任意受限 JSON 值，
包括 object、array、string、number、boolean 和 null。

`content` 不是该壳的字段名。SSP 的 `Publish.content_json` 是承载 CP 报文的外层概念，
业务事件若称为 `content`，也必须放在 `body` 的业务结构中。

## 2. 签名

签名逻辑对象为：

```json
{
  "scope": "bsv8.public-message.v1",
  "channel": "exact-channel",
  "from_public_key": "02...",
  "message": {
    "message_id": "...",
    "issued_at_ms": 0,
    "expires_at_ms": 0,
    "body": {}
  }
}
```

对象先按 RFC 8785 JCS 输出 UTF-8，再计算 SHA-256，最后使用 secp256k1 ECDSA 生成
strict DER、low-S 签名。SSP `request_id`、连接公钥、付款身份和传输元数据不进入签名。

消息有效期不得超过 `600_000 ms`；验签时发布时间最多可以领先本地时钟 `60_000 ms`。
`now_ms == expires_at_ms` 已过期。JSON 输入、body 的 JCS 规范化和构造结果都遵守共享的
字节、深度和节点上限。

## 3. 去重与信任边界

公开消息去重键固定为：

```text
(channel, from_public_key, message_id)
```

只有三元组完全相同才比较签名逻辑摘要；不同摘要返回 `MESSAGE_ID_CONFLICT`。因此，
两个不同频道可以使用相同作者和 `message_id`，不会误判为重复。

Go `VerifiedMessage` 保存防御性 JSON 快照；TypeScript 验签结果由模块私有运行时品牌
标记并递归冻结。只有 SDK 生成的已验证值可以进入只接受 verified 值的去重和关系操作。

## 4. 与固定频道的关系

通用壳只验证 JSON、时间和签名，频道对应的业务语义由上层负责。`HashRequest` 仍是
`bsv8.hash.request.v1` 的固定频道强类型模块，拥有自己的 `HashRequestBody` 和 locator
校验；通用公开消息不会废弃或替代它。

SDK 使用：

- Go：`github.com/bsv8/ChannelProtocol/publicmessage`；
- TypeScript：`bsv8-channel-protocol/public-message`。

两端的 `body` 字段、JCS 字节、摘要、签名和三元去重键使用相同 V1 向量。
