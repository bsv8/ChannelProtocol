## 1. 背景与基线判定

`keymaster.cc` 当前通过 `bsv8-channel-protocol@0.2.0.patch` 提前使用以下能力：

- 任意精确公开频道的统一签名消息；
- `verifySignedPrivateMessage`，用于将本地已签名 Ping/WebRTC 消息提升为可参与关系校验的已验证值；
- 公开消息和私密子协议的 TTL 常量与查询函数；
- `bsv8-channel-protocol/public-message` npm 子路径。

本仓库已有与该补丁编译产物逐文件一致的暂存源码，但尚未提交、打标签或发布。已发布的 npm `latest` 仍为 `0.2.0`。

当前候选源码不得直接发布，因为存在以下收口问题：

1. Go `publicmessage.VerifiedMessage` 保留并返回可变 `map`/`slice`，验签后内容可被篡改；
2. TypeScript `VerifiedPublicMessage` 是可伪造的结构类型，没有模块私有品牌；
3. 通用公开消息实现使用线上字段 `content`，与 V1 总览已冻结的 `body` 不一致；
4. 通用公开消息的去重键缺少 `channel`，不满足 `(channel, from_public_key, message_id)` 的现有规则；
5. Go/TypeScript 公开 API 表面、TTL 命名和验证结果约束未完全对齐；
6. 新增通用公开消息没有共享 fixture、跨语言向量和完整边界测试；
7. 根 README、TypeScript README、V1 文档和 `protocols.json` 尚未反映新原语。

## 4. 必须先冻结的协议与 API 决策

### 4.1 通用公开消息线上形状

线上 JCS JSON 固定为：

```json
{
  "from_public_key": "02...",
  "message_id": "base64url-32-byte",
  "issued_at_ms": 0,
  "expires_at_ms": 0,
  "body": {},
  "signature": "base64url-der"
}
```

规则：

- 传输 JSON 和 Go/TypeScript SDK 类型统一使用 `body`；
- `channel` 不进入 JSON，但必须进入签名逻辑对象；
- 签名逻辑对象仍使用 `scope = "bsv8.public-message.v1"`；
- `body` 可为任意受限 `JSONValue`，但必须通过 JCS、深度、节点数和总字节上限；
- `content` 是 SSP `content_json` 或业务层事件概念，不是 CP 公开壳的字段名。

### 4.2 去重与冲突

通用公开去重键必须是：

```text
(channel, from_public_key, message_id)
```

- Go `DeduplicationKey` 和 TypeScript `DeduplicationKey` 都必须包含 `channel`；
- 两个不同频道可使用相同作者和 `message_id`，不得被当作重复；
- 只有去重键三元组相同时才检查 digest 冲突；
- `checkDigestConflict` 必须在 Go/TypeScript 两端对称存在，不同 digest 统一返回 `MESSAGE_ID_CONFLICT`。

### 4.3 时间常量

- 通用公开消息最大有效期固定为 `600_000 ms`；
- 未来时钟容差固定为 `60_000 ms`；
- Ping/Pong 私密消息为 `60_000 ms`；
- WebRTC 私密消息为 `120_000 ms`；
- 其他已支持私密消息为 `86_400_000 ms`。

Go 保持现有风格，通过 `MaxLifetimeMs()` / `MaxFutureSkewMs()` 以及 inbox 层的有效期查询函数对外提供；TypeScript 保留语义明确的大写常量和 `privateMessageMaxLifetimeMs`。不保留会污染根入口的泛化 `MAX_LIFETIME_MS` 别名。

### 4.4 已验证值信任边界

- Go `VerifiedMessage` 的内部快照与所有访问器返回值不得共享可变 map/slice；
- TypeScript `VerifiedPublicMessage` 必须由模块私有 `WeakSet` 品牌化；
- TypeScript 对外提供 `isVerifiedPublicMessage`，`dedupKey` 和其他只接受已验证值的操作必须先检查品牌；
- `Object.freeze` 不得只停留在顶层，必须递归冻结 `body`；
- 本地已签名私密消息只能经 `verifySignedPrivateMessage` 验证签名、时间、channel 和子协议后获得同一个已验证品牌。

## 5. 阶段 0：先写失败测试与共享向量

在修改实现前增加：

- `testdata/v1/public-message-valid.json`；
- `testdata/v1/public-message-invalid.json`；
- Go 共享 fixture 驱动测试；
- TypeScript 共享 fixture 驱动测试；
- Go 快照可变性回归测试；
- TypeScript 伪造 verified 值的负面测试。

合法向量至少包含：

1. 固定私钥、公钥、精确 channel、message_id 和时间；
2. 同时含 object、array、Unicode、boolean、null 和 JSON number 的嵌套 `body`；
3. 预期规范 JSON UTF-8/十六进制；
4. 预期签名逻辑摘要和 strict DER low-S 签名；
5. 预期 `(channel, from_public_key, message_id)` 去重键；
6. 有效期和未来时钟容差的精确边界值。

非法向量至少包含：

- 空 channel、`*`、控制字符、超过 256 UTF-8 字节和非法 Unicode；
- 缺少必需字段、额外字段、重复 JSON key 和错误字段类型；
- `content` 字段作为旧候选形状必须返回 `UNKNOWN_FIELD`；
- `issued_at_ms >= expires_at_ms`；
- 有效期分别为 `600_000` 和 `600_001 ms`；
- 未来偏差分别为 `60_000` 和 `60_001 ms`；
- `now_ms == expires_at_ms`；
- 错误公钥、错误签名、high-S、篡改 channel、body、message_id 和时间；
- 超过 JSON 字节、深度和节点上限；
- 相同三元去重键下的不同 digest。

本阶段结束时，可变快照、伪造 verified、`content` 旧形状和跨频道去重测试必须先稳定失败。
